# 第一轮稳定性修改

更新于 2026-11-13。保留 Python 标准库后端、现有页面和原 greenvideo 解析脚本。

## 用户可见的变化

- 已下载视频按视频 ID 查重；标题重命名和跨日期保存不影响识别。
- 旧数据通过每条视频的“视频信息”记录及旧 `video_<id>.mp4` 名称识别，无需批量迁移。
- 新下载先写临时文件，检查命令退出码、HTTP 错误和 MP4 容器结构后再保存为正式视频。
- 成功数表示当前所选流程已完成；开启转写时，下载成功但转写失败会显示失败。部分成功显示“部分失败”。
- 每条视频单独显示下载、转写状态及失败原因。点击条目标题打开该视频实际目录。
- “重试未完成项”仅处理上次任务中未完成的条目；有效视频跳过下载，原始稿可用时仅重新合并。
- 转写上传 token 和妙记 token 立即保存；普通超时重试复用已有任务。
- 飞书明确返回远程任务失败时保留失败记录；点击重试后，界面询问是否重新创建妙记，可能消耗额度。确认后复用已上传文件。
- 空转写正文不能标记为完成。已有妙记 token 的空稿可重新获取；无说话人标记的普通正文会保留。
- 停止、退出及子命令超时使用 Windows Job Object 清理任务及其子进程。停止完成前不接受新任务。
- 工作记录保存在 `work/last_job.json`，服务重启后上次未完成任务可重试。

## 保存的数据

每条视频目录新增 `task_state.json`，包含视频 ID、下载文件名、下载状态、转写状态、飞书 file/minute token、失败原因和用量记录标志。状态及转写产物原子写入。

用量台账新增按 minute token 去重，防止记账后、检查点写入前中断导致重复记录。旧记录保留。台账损坏时报告错误而不覆盖原数据。

检查点损坏时停止并报告，避免悄悄丢弃远程 token 后重复上传。请保留状态文件和现有 work 数据。

## 启动与环境

原桌面快捷方式引用的 WorkBuddy Python 3.13.12 已不存在，该虚拟环境也不能启动。本轮部署将快捷方式改用机器上可运行的 Python 3.13，并保留原运行目录、图标和参数；原快捷方式会一同备份。

当前可用解释器：

```
<python.exe>
```

Node 与 lark-cli 仍由 `app/envpath.py` 补充路径。下载时不自动安装或升级环境。当前解释器未安装可选的 yt-dlp；该方式失败后仍进入原 greenvideo 解析流程，界面会如实显示 yt-dlp 不可用。

## 验证

在实际准备使用的 Python 3.13 中通过 32 项回归测试：

```
python -m unittest discover -s tests -v
```

覆盖重命名后查重、跨日期复用、curl 非零与残缺文件、部分失败、转写 token 分阶段恢复、空稿、原稿合并、限流、CLI 非零、远程终态失败重建、记账幂等、服务恢复、即时停止、真实进程树停止与句柄关闭、真实 cmd 子命令超时清理，以及本地 HTTP 的开始→部分失败→只重试失败项→完成→退出。

前端脚本通过 Node `--check`。测试使用合成 MP4 和 mock 飞书响应；没有调用真实收费转写、没有测试新的抖音在线下载，也没有将收藏夹验证码问题视为解决。

MP4 检查验证容器边界、非空媒体负载、正时长电影头和视频轨道，不等同于逐帧解码。远程操作完成与 token 本地落盘之间仍存在极小的中断窗口；无法宣称云端操作严格只执行一次。

## 备份和回滚

同步脚本只覆盖清单中的源码、测试和说明，不覆盖 cookies、浏览器配置、原视频、原文案及现有用量台账。运行目录内 `.round1-backups/<时间>/` 保存被替换的原文件和原桌面快捷方式，部署后打印确切路径与回滚命令。

回滚前先退出控制台，运行备份中的 `rollback.ps1`。它恢复被替换的旧文件和快捷方式；新添的模块与测试保留但旧入口不引用它们。
