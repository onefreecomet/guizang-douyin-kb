# P2：知识结构的自动加工

本文件说明 P2 实际做了什么、边界在哪里、怎么回退。设计稿见工作区的 `AUTOPILOT.md`，实现边界见 `P2-CONTRACT.md`（内部契约，不部署）。

P1 的边界（定时扫描、下载、飞书转写、写入 Obsidian、控制台）见 `P1.md`。

## 本期做了什么

1. **AI 加工**（`app/enrich.py`）：对每条视频的转写文本调用一次模型，得到摘要、要点、主题、系列归属，写进笔记。纯标准库实现，不需要额外依赖。
2. **知识库派生页**（`app/knowledge.py`）：由素材笔记自动生成
   - `主题/<主题名>.md`：主题简介、该主题下的相关视频；
   - `系列/<系列名>.md`：系列综述、按集号排列的分集；
   - `00 - 索引.md`：统计、最近入库表、按主题浏览、系列、待处理。
3. **主题合并**：`POST /api/kb/topic/merge` 把源主题并入目标主题，改写相关素材的 `topics` 与正文主题行；原主题页保留为 `kept_page: true` 的别名页，不再出现在主题列表里。
4. **流水线新增「AI 加工」阶段**：下载 → 转写 → AI 加工 → 发布 → 派生页刷新。AI 失败不阻断入库，笔记照常生成，队列里记 `warning`，可稍后「补齐 AI 加工」。
5. **控制台接入**：知识库页可在素材/主题/系列三视图间切换，支持预览主题页与系列页、刷新知识库、补齐 AI 加工、合并主题；设置页可配置 AI 开关、接口地址、模型、每日上限与密钥；自动同步页显示今日 AI 用量。

## 配置

在控制台「设置」里填写，保存在运行目录 `work/config.json`：

| 字段 | 说明 |
| --- | --- |
| `ai_enabled` | 是否启用 AI 加工，默认开启 |
| `ai_base_url` | OpenAI 兼容地址，例如 `https://amr-link.open-design.ai/v1` |
| `ai_model` | 模型名，例如 `deepseek-v4.1-flash` |
| `ai_api_key` | 密钥。只写入不回显；设置页留空表示不修改 |
| `ai_daily_limit` | 每日最多加工几条，1–2000，默认 200 |

- 未启用或未填密钥时，流水线跳过 AI 阶段，笔记 `status` 保持 `待加工`，不会报错。
- 用量账本：`work/ai_usage.json`（按日期累计条数与 token），不是新的数据库。

## 笔记与页面格式

素材笔记 frontmatter 在 P1 字段基础上增加：`ai_summary`、`key_points`、`topics`、`series`、`series_index`、`ai_model`、`ai_at`，并把 `status` 从 `待加工` 改为 `已加工`。

正文顺序：摘要 callout → 要点 → 原文（带时间戳）→ 基础信息 → 主题/系列链接 → 视频文案 → 本地视频链接。

主题页、系列页、索引页都遵循同一套保护：

- 程序只重写 `<!-- AUTO:START -->` 与 `<!-- AUTO:END -->` 之间；
- 页面里你自己加的其他字段、`## 我的笔记` 之后的内容一律不动；
- 页面被手改坏（AUTO 区块损坏、frontmatter 未闭合）时跳过该页，不影响其他页生成；
- 内容没有变化就不写盘，避免同步插件产生无意义的版本。

## 冻结

素材 `status` 为 `已定稿` 或 `冻结` 时：

- 素材笔记完全跳过重写（字节不变）；
- 主题合并时计入 `frozen` 计数但不改写；
- 它们引用的主题/系列仍会出现在派生页里。

## 接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/kb/topics` | 主题列表（名称、父主题、条目数、页面路径） |
| GET | `/api/kb/topic?name=` | 读主题页，不存在则先生成空页 |
| GET | `/api/kb/series` | 系列列表 |
| GET | `/api/kb/series/note?name=` | 读系列页 |
| GET | `/api/ai/usage` | 今日用量、上限、是否已设置密钥 |
| GET | `/api/kb/tree` | 目录树，附带 `topics` 与 `series` |
| POST | `/api/kb/refresh` | 重建派生页与索引 |
| POST | `/api/kb/topic/merge` | 合并主题（`source`/`target`，也接受 `from`/`to`） |
| POST | `/api/kb/enrich` | 为已入库但未加工的笔记补 AI 加工（单次最多 3 条） |
| POST | `/api/ai/test` | 用当前配置做一次最小真实调用，验证连通性 |

`/api/settings` 提交时空字符串的 `ai_api_key` 表示「不修改」，密钥永远不回显。

## 启动与调度

与 P1 相同：`pythonw.exe app\server.py --port 8765`，或双击桌面快捷方式。每日 04:00（北京时间）自动跑一次，白天不做周期扫描；手动「立即同步」仍然可用。AI 加工只在该次流水线里进行，不会额外定时调用模型。

## 验证情况

- 工作区与运行目录全量各 `Ran 168 tests / OK`（P1 结束时为 104 项）；其中 `tests/test_enrich.py` 51 项使用本地 mock 的 HTTP 服务，`tests/test_knowledge.py` 24 项覆盖派生页、合并、冻结、幂等，`tests/test_autopilot_api.py` 覆盖新增端点的真实 HTTP 行为与 AI 探测的错误分流。
- 真实模型已验收一次（2026-11-13 15:19）：对已入库的唯一一条 10 分钟收藏调用 `deepseek-v4.1-flash`，产出中文摘要、8 条要点、主题「阿努纳奇与苏美尔神话」、系列「阿努纳奇起源故事」第 1 集，用量 3978 tokens，`status` 变为 `已加工`，主题页/系列页/索引页同时生成；再次点「补齐 AI 加工」返回空列表（按 `ai_summary` 幂等跳过）。
- 推理型模型的坑（已在代码里处理）：该模型会先花掉 completion 预算做 reasoning，`max_tokens` 给小了会返回 `choices: []`。现已把探测请求上限提到 512、正式加工上限提到 4096，并把「只返回思考过程」与「格式不符合预期」区分成两条错误文案。
- 未验证：真实计费明细（账本按 API 返回的 usage 累计，不是账单核对）、真实抖音页面的扫描、真实付费转写、真实飞书通知。这些都需要在有人在场的情况下单独验收。

## 回退

本期部署前会把运行目录的旧文件备份到 `.p2-backups/<时间戳>/`（含 `manifest.json` 与 `rollback.ps1`）：`20261113-151004`（首次 P2）、`20261113-151231`（索引页竖线转义与待处理过滤）、`20261113-152115`（推理型模型适配）、`20261113-152423`（系列字段归一化）。回退时先 `POST /api/quit` 停服，再运行对应目录的 `rollback.ps1`，然后重新启动服务。知识库里已经生成的素材笔记不会因回退消失，但 P2 生成的 `主题/`、`系列/`、`00 - 索引.md` 需要手动删除。
